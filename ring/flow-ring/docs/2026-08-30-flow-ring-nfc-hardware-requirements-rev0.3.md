0. 开工前必读与执行顺序

1. 确认拿到本文件、原始系统设计文档、现有 PCB 布局草案和机械包络数据；在版本库建立独立硬件开发分支。
1. 选择团队能够持续维护的 EDA 工具，建立受版本控制的正式工程；现有布局草案只作为分区参考，不得在图片、PDF、Gerber 或其他不可编辑导出文件上继续设计。
1. 从 Nordic、TI、ST、Microchip，以及电芯和天线厂商处取得当前正式资料，记录文档版本、下载日期和校验值。
1. 在开始原理图前提交《输入冻结与 RFI 清单》，至少覆盖电芯、天线、触摸封装、板厂 HDI 能力、充电座和结构 CAD。
1. 完成 Gate H0 后再重建原理图；完成原理图评审、封装复核和电源预算后，才允许进入 Layout。
1. 只有 Gate H2 书面通过，才允许生成制造文件和下单；禁止把“EDA DRC 为 0”当成下单授权。

1. 文档目的、范围与优先级

- GEN-001  本文件是 Flow Ring 定制硬件 EVT 的执行基线，负责定义电气设计、PCB、结构协同、可制造性、试产、测试和交付证据。
- GEN-002  软件协议、手势算法和 RK3588/App 实现仅作为接口约束；硬件工程师不得重定义四手势、BLE 业务语义或音效库。
- GEN-003  冲突优先级：经批准的工程变更单 > 器件/电芯最新正式规格与勘误 > 本文件 > 概念稿与占位工程。发生冲突必须提出 RFI，不得静默修正。
- GEN-004  所有 MUST/必须/不得条款均为放行条件；建议项如被拒绝，工程师应记录理由、替代方案和风险。
  
2. 项目目标与非目标

2.1 EVT 目标

- OBJ-001  完成一块可以装入 M60 印章式戒指电子舱的 21 × 15 mm 定制硬件，验证 BLE、IMU、触摸、充电、功耗和人体加载下 RF。
- OBJ-002  保持与 XIAO nRF54L15 Sense 软件平台一致，但最终板使用 nRF54L15 裸片和独立器件，不把 XIAO 开发板装入戒指。
- OBJ-003  为 8 小时目标提供可实测的功耗、电池和充电设计；电池容量在实测前保持开放。
- OBJ-004  产出可复现的 EDA 源文件、制造资料和验证报告，使下一轮能够基于证据进入 DVT。
  
2.2 本轮非目标

- 不做 rigid-flex、弧形电池或细戒圈量产外观；这些属于 EVT 通过后的 DVT。
- 不设计金属戒圈或带金属涂层的天线区域。
- 不在戒指上增加音频播放、麦克风、USB-C 或与产品无关的传感器。
- 不设置振动马达、触觉驱动芯片、蜂鸣器或其他本地反馈执行器；识别结果由 BLE 发送给外部设备处理。
- 不在未选定电芯、天线和板厂工艺前给出量产 Gerber。
- 不把第一轮小批量样机直接定义为认证或量产版本。

5. 系统架构与功能边界

硬件链路：定位 pogo 充电座 → 充电/电源管理 → nRF54L15 + RF；nRF54L15 连接 IMU 和触摸控制器；受保护单节 LiPo 为整机供能。戒指本体不设置震动或其他本地反馈执行器。

- SYS-001  戒指为 BLE Peripheral / GATT Server；原始 IMU 不进入量产实时链路。
- SYS-002  拇指触摸是手势识别门控；一次稳定触摸最多产生一个音效事件。
- SYS-003  硬件必须支持触摸门控、本地 208 Hz IMU 短时采样、BLE 事件发送、业务 ACK 状态处理和低功耗空闲；业务 ACK 不触发戒指本地震动。
- SYS-004  最终板不保留 PDM 麦克风；IMU 应具有独立可控电源域。

9. nRF54L15、时钟和射频核心

- RF-001  以 Nordic CSP47 (CAAA) 官方 Reference Layout 为设计原点；截至 2026-08-29 官网列出 v0.7，开工时必须再次检查最新版本并记录。
- RF-002  整体复制参考电路中的电源、DC/DC、32 MHz/32.768 kHz、去耦、谐波滤波、RF 匹配、接地和关键相对位置；不得为节省面积任意压缩。
- RF-003  保留天线侧 π 匹配网络和可接触的 50 Ω 调试位置；测试板可加微型 RF 接口或探针焊盘，正式板再 DNP/移除。
- RF-004  RF 馈线的 50 Ω 线宽/间距只能在板厂层叠、铜厚和介质参数确认后计算，并由板厂提供阻抗 coupon/报告。
- RF-005  RF 区下方连续参考地不得被电源缝、触摸窗口、测试焊盘或机械开槽切断。
  
10. 天线与人体加载

- ANT-001  天线放在顶部外沿，朝离手指最远方向；keep-out 内各层禁铜的具体尺寸由天线数据手册和供应商 review 决定。
- ANT-002  天线附近禁止磁铁、金属壳、金属喷涂和连续金属戒圈；充电座磁体也需评估收纳/充电状态的影响。
- ANT-003  必须测试裸板、装壳、戴在手上、拇指触摸四种状态；至少记录匹配、RSSI/连接距离、丢包和方向性。
- ANT-004  天线型号未冻结前不得下单正式 PCB；建议让天线厂商和 Nordic 分别 review placement、keep-out 与匹配网络。
  
11. IMU 与机械噪声控制

- IMU-001  U2 靠近板中心，底部保持平整，远离板边、螺柱、开槽和高电流开关回路。
- IMU-002  在 F.SilkS、装配图和结构 CAD 同时标出 Pin 1、X/Y/Z 轴和戒指前向；壳体必须防止 PCB 旋转。
- IMU-003  硬件支持 208 Hz 六轴采样；最终量程、ODR、滤波和中断配置由固件与数据集共同冻结。
- IMU-004  记录触摸、BLE 发射、充电和佩戴结构应力对 IMU 噪声及零偏的影响；不得依靠固定丢帧窗口掩盖硬件干扰。
  
12. 电容触摸设计

- TOUCH-001  有效电极以约 8 × 6 mm 为起点，位于食指内侧；通过至少两种电极/覆盖层 coupon 验证，不直接冻结成量产尺寸。
- TOUCH-002  覆盖层先按 0.8–1.2 mm 非金属材料试制；测试汗液、干手、湿手、手套、戴/脱戒指、充电和 BLE 发射状态。
- TOUCH-003  AT42QT1010、Cs、Rs 靠近布置；SNS/SNSK 到电极走线短，远离 buck SW、晶振和天线馈线。
- TOUCH-004  UDFN/USON 裸露中心焊盘按 Microchip 要求接地，芯片本体下只允许地，不走其他信号。
- TOUCH-005  预留 2–3 个 Cs 值、串联电阻和必要 DNP 位；最终参数在成品外壳上通过灵敏度和误触测试冻结。
  
13. 本地反馈功能边界

- FB-001  戒指本体不安装振动马达、LRA、ERM、压电执行器、蜂鸣器或触觉驱动芯片。
- FB-002  PCB 不为 DRV2605L、C08-00A 或同类器件预留专用封装、接口、储能电容和结构空间，避免形成无需求的面积、功耗和 BOM 负担。
- FB-003  手势识别结果、成功/失败和业务 ACK 通过 BLE 上报；声音、画面或触觉反馈由手机、接收端或其他外部设备实现。
- FB-004  调试阶段可以使用开发板 LED 或日志显示状态，但该行为不构成最终戒指硬件需求。
  
14. 电池、充电和 pogo

- BAT-001  电池可采用顶部舱内微型矩形电芯或沿戒圈布置的预成形弧形电芯。当前 150723 弧形电芯仅作为样品候选；必须确认 R10.2 的半径基准、L32 是弧长还是弦长、尺寸公差、膨胀和极耳空间后才能冻结结构。严禁强行弯曲普通平面软包电芯。
- BAT-002  电芯必须有可追溯供应商、容量/内阻/最大充放电/终止电流/温度范围/循环寿命/膨胀/保护与 NTC 资料。
- BAT-003  充电电流、终止电流、充电电压和 JEITA/NTC 配置必须与电芯成套冻结；不得沿用 XIAO 约 200 mA 默认充电思路。

23. 上电与 Bring-up 顺序

1. 断电检查所有电源到地阻抗、二极管方向、pin 1、焊桥、X-ray 和装配差异；未通过不得接电芯。
1. 使用限流电源从充电输入/电池路径分别上电，确认 PMIC、SYS、1.8 V、ship mode 和静态电流。
1. 验证 SWD、RESET、芯片识别、擦写、32 MHz/低频时钟和最小固件。
1. 验证 BLE 广播、连接和电流；完成 RF 调试接口/匹配网络的基线测试。
1. 开启 IMU 电源，验证地址、WHO_AM_I、INT、轴向、208 Hz 数据和掉电反灌。
1. 验证 AT42QT1010、TOUCH_OUT、不同 Cs/覆盖层和充电噪声。
1. 接入实际电芯，验证充电电流、终止、NTC、温升、充满/欠压/重启和 8 小时压力模型。
1. 装壳后重复 RF、触摸、IMU、电池、功耗和佩戴测试。

附录 D：NFC 功能增补（Rev 0.3，2026-08-30）

> 本附录只增加 NFC 开发需求。前述 Rev 0.2 的机械尺寸、BLE、IMU、触摸、电池、无本地触觉反馈及其他既有要求保持不变。发生冲突时，除本附录明确增加的 NFC 项外，仍以前述原文为准。

D.1 产品用途与硬件角色

- NFC-HW-001  戒指使用 NFC 保存并近场提供舞者的音乐风格、舞种、BPM、能量和 groove 偏好，使 RK3588 Hub 能依次刷取 4–5 枚戒指并建立一次 cypher 的参与者偏好集合。
- NFC-HW-002  nRF54L15 的 NFCT 只作为 13.56 MHz NFC-A listening device，也就是“戒指标签端”；戒指不得被设计成主动读卡器。
- NFC-HW-003  RK3588 Hub 必须增加独立 NFC polling/reader-writer 硬件。该硬件至少支持 NFC-A、ISO/IEC 14443-4（ISO-DEP）、NFC Forum Type 4 Tag 读写；需要双向业务交换时还必须支持应用层 TNEP 流程。
- NFC-HW-004  NFC 只负责近场身份与偏好交换，不替代现有 BLE 手势事件、ACK、音效触发和设备管理链路。
- NFC-HW-005  戒指侧不增加单独 NFC 控制器作为默认方案，优先使用 nRF54L15 内置 NFCT；只有“电池完全耗尽仍能读取档案”被提升为硬性需求时，才允许通过 RFI 评估带能量采集/非易失存储的外置动态 NFC Tag。

硬件链路增补：

`RK3588 Hub → 外置 NFC 读写器及 Hub 天线 ⇄ 13.56 MHz 近场 ⇄ 戒指 NFC 环形天线 → NFC1/NFC2 → nRF54L15 NFCT → 舞者档案非易失存储`

D.2 开发板阶段接口

- NFC-DEV-001  XIAO nRF54L15 Sense 的 `NFC1/P1.02` 和 `NFC2/P1.03` 必须保留给 NFC，禁止在开发板 overlay、原理图或测试夹具中复用为 GPIO。
- NFC-DEV-002  XIAO 板阶段必须在 NFC1、NFC2 之间连接外部差分 13.56 MHz 环形天线；两个天线端无极性，但走线必须成对、短、对称，并避开 USB、开关电源和 2.4 GHz 天线区域。
- NFC-DEV-003  开发板试验不得以“手机能够偶尔读到”为完成标准。必须记录天线型号、线圈电感、匹配电容、外壳状态、供电状态、读取方向、距离和成功率。
- NFC-DEV-004  开发板 Bring-up 先验证 Nordic nRF Connect SDK 的 Type 4 Tag/NDEF 能力，再接入舞者档案；不得直接从复杂业务排查天线或底层协议问题。

D.4 NFC 天线、布局和结构

- NFC-ANT-001  EVT 至少比较两种可制造天线方案：电子舱上盖 FPC/绕线环与 PCB 周边线圈；若戒圈内布线可制造，可作为第三方案。最终方案由耦合、结构、舒适性和一致性实测决定。
- NFC-ANT-002  天线有效区域不得被电池、磁体、金属紧固件、金属涂层、屏蔽罩或大面积铜直接覆盖。结构 CAD 必须标注“Hub 刷取面”和禁止金属区。
- NFC-ANT-003  13.56 MHz 天线与 2.4 GHz BLE 天线、触摸电极、电池和充电磁体必须联合布局。任何一项位置调整都要复测 NFC、BLE、触摸和充电噪声，不得单独优化 NFC 后直接冻结。
- NFC-ANT-004  调谐必须分别在裸板、装壳、装电池、佩戴手指以及靠近 Hub 天线五种状态下记录；最终匹配以“装壳、装电池、正常佩戴并靠近 Hub”状态为主。
- NFC-ANT-005  天线供应商或 RF 工程师须提供 13.56 MHz 阻抗/谐振测量、匹配值和容差分析。天线几何、铜厚、FPC 叠层、连接方式或外壳材料变化后必须重新确认。
- NFC-ANT-006  Hub 外置 NFC 天线要形成清晰、单人可控的刷取区，避免同时耦合相邻两枚戒指。Hub 金属机壳、散热器和 RK3588 主板噪声必须纳入 reader 天线布局及屏蔽评审。

D.5 电源、可靠性与安全

- NFC-PWR-001  功耗预算增加 `NFCT SENSE`、场唤醒、Type 4 交换、档案校验和非易失写入四种状态；不得只测空闲平均电流。
- NFC-PWR-002  System OFF 场唤醒后会发生系统复位，启动代码必须能识别 NFC 唤醒原因并在 Hub 等待窗口内准备好 Tag 服务；硬件验证需覆盖冷启动、低电量和临界欠压。
- NFC-PWR-003  NFC 写档案期间掉电、移开戒指或 Hub reader 复位不得损坏旧档案。硬件必须允许固件采用双槽/日志式原子提交，并为最坏写入峰值提供稳定电源。
- NFC-PWR-004  强场、长时间贴放、充电同时刷取和连续 100 次刷取时，不得出现电池异常回灌、PMIC 锁死、异常发热、触摸误触或 BLE 永久掉线。
- NFC-SEC-001  NFC 近距离不等于身份可信。硬件必须保留 nRF54L15 安全存储和加密能力，不得为调试方便在量产配置中关闭安全启动、读保护或密钥保护。

D.6 Hub NFC 读写器选型门禁

- HUB-NFC-HW-001  选型前必须提交 reader 芯片/模块、Linux 驱动、接口方式、天线与匹配资料、ISO-DEP/Type 4/TNEP 支持证据及供应状态。
- HUB-NFC-HW-002  首选 Linux 下有长期维护驱动和稳定用户态 API 的 USB、UART、SPI 或 I²C 方案；具体接口由 Hub 硬件资源和驱动验证决定，不在本附录凭空冻结料号。
- HUB-NFC-HW-003  Reader 必须能读取戒指 NDEF 档案，并在启用双向交换时向 Type 4 Tag 写入请求、读取响应；只支持 UID/MIFARE 私有命令的廉价模块不满足要求。
- HUB-NFC-HW-004  Hub reader 必须提供可控 RF 场开关、操作超时、错误码和场内多标签处理策略。产品交互一次只接受一枚明确贴近的戒指。

D.7 Bring-up 与验证增补

在原第 23 节 Bring-up 中，完成 BLE 最小验证后、开启 IMU 前插入以下步骤：

1. 核对 NFC1/NFC2 无短路、无 GPIO 复用，测量线圈和匹配器件实装值。
1. 烧录 Nordic Type 4 Tag/NDEF 最小示例，使用已知合格 NFC polling device 完成 100 次读测试。
1. 验证 NFCT field detected/field lost、System ON 和 System OFF 场唤醒。
1. 接入 Hub reader，验证 ISO-DEP 激活、NDEF 读取、写入、移开中断和恢复。
1. 加入真实舞者档案后，再执行装壳、佩戴、BLE/触摸/IMU 并发和低电量测试。

D.9 开放项与停手条件增补

以下项目在 Gate H1 前必须关闭：

- 最终 NFC 天线形式、可用面积、刷取面和匹配责任人。
- Hub reader 芯片/模块及其 ISO-DEP、Type 4、TNEP 和 Linux 支持证据。
- 是否要求电池耗尽仍可读；如要求，必须重新评估外置动态 NFC Tag、电源与空间。
- 舞者档案是否允许 Hub 通过 NFC 写回；如允许，必须同步冻结软件鉴权、掉电保护和密钥装配流程。
- 电芯、PMIC 与 nRF54L15 在强 NFC 场下的反向电流容限和保护方案。

出现以下任一情况必须停手并提交 RFI：

- 结构无法提供无金属 NFC 刷取面，或天线被电池/磁体完全遮挡。
- 要求戒指主动读取其他 NFC 标签；nRF54L15 NFCT 不具备 polling/reader 角色。
- Hub 候选模块只能读 UID 或私有卡片，无法完成 ISO-DEP/Type 4 NDEF。
- 开发板或定制板把 P1.02/P1.03 分配给其他关键功能。
- 未验证强场回灌就要求冻结电池和电源设计。
